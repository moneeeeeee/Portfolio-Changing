Clinical Analytics Dashboard

Developer | R, Shiny, tidyverse, ggplot2

Overview

An R Shiny dashboard, used by 35+ staff, that traces a tumour variant through evidence, interpreted action, treatment and response.

Answering a question such as “which patients share this alteration, what were they treated with, and how did they respond?” meant manually querying several large tables kept in different places. I set out to bring those views into one interactive tool.

Key Numbers

35+staff users
8tabs: 5 tables, 3 plot views
5data layers unified
4documented workflows

Tools

  • R
  • Shiny
  • tidyverse
  • ggplot2

Role

Developer. Co-op project at Canada's Michael Smith Genome Sciences Centre (BC Cancer) (Sept 2025 – Apr 2026).

Description

  • Unified 5 data layers in one app: knowledge-base matches, therapeutic actions, treatment records, drug-class mappings and treatment outcomes.
  • Built 5 filterable data tables and 3 plot views, with sample filters synchronized across tabs and interdependent gene and drug filters.
  • Added a compound search builder, column reordering and export of the filtered view to Excel.
  • Implemented the mapping from treatments given back to drug classes, which enables response and duration plots by tumour type and treatment class.
  • Built concordance plots comparing knowledge-base matches with the clinical actions taken.
  • Deployed the app on an internal Linux server and wrote a 10-page user guide with 4 worked analysis workflows and known limitations.

Outcome

Users can start from a sample, a gene or a drug class and follow it across the other views without writing queries. The app is not meant to replace review; it makes review faster and more connected. Writing the user guide taught me that a tool is finished only when the people it is for can use it without me.
